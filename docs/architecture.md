# 시스템 아키텍처

작성일 2026-09-30 · v1

이 문서는 **코드를 어떻게 배치하는가**를 담는다.
왜 그렇게 정했는지는 `design.md`에 있고, 작업 규칙은 `CLAUDE.md`에 있다.

**코드를 쓰기 전에 이 문서를 읽는다.** 여기 정한 모듈 경계와 타입을 지킨다.

---

## 1. 폴더 배치

```
세특검토기/
├─ CLAUDE.md                작업 규칙. 항상 읽힘
├─ config.py                모든 설정값. 여기 말고 다른 곳에 두지 않는다
├─ .gitignore
├─ .claude/
│  └─ settings.json         도구 권한
├─ docs/
│  ├─ design.md             판단 근거
│  ├─ architecture.md       이 문서
│  └─ data_notes.md         전처리 내역 (개인정보 처리 근거)
├─ data/                    ← 전부 .gitignore 대상
│  ├─ regulations/          규정 md 23개. 원본 그대로        → 색인함
│  ├─ domain/               교사 관습·암묵지. 증언과 현장 관찰  → 색인함 (03 제외)
│  ├─ classification.md     조항 5종 분류표 (0-2 산출물)       → **색인 안 함**
│  └─ eval/                 평가셋                            → 색인 안 함
├─ src/
│  ├─ store/                검색 자료를 만들고 검색한다
│  ├─ reviewer/             세특 문장 검토기
│  ├─ generator/            세특 초안 생성기
│  └─ common/               타입·로그
├─ tests/
├─ logs/                    ← .gitignore 대상
└─ app.py                   Streamlit 진입점 (5단계)
```

### 1.1 폴더별 역할

| 폴더 | 무엇이 들어가나 | 색인 | 언제 만드나 |
|---|---|---|---|
| `data/regulations/` | 기재요령·길라잡이 인용본 md 23개. 원문 그대로 | `regulation` | 완료 (0-0) |
| `data/domain/` | **교사 관습·암묵지·도메인 지식.** 증언, 현장 관찰, 추가 취재분 | `domain` | 완료 0-1 |
| `data/eval/` | 평가셋. 위반:정상 ≈ 1:1 | — | 2단계 |
| `data/classification.md` | 조항 5종 분류표. 판정 프롬프트 만들 때 본다 | — | 0-2 |
| `docs/` | 규칙·근거·전처리 내역 | — | — |
| `src/store/` | 문서를 자르고 저장하고 검색한다 | — | 1-a·1-b |
| `src/reviewer/` | 문장을 받아 판정한다 | — | 1-c·1-d |
| `src/generator/` | 활동 기록을 받아 초안을 만든다 | — | 3단계 |
| `src/common/` | 공통 타입·로그 기록 | — | 1-a |
| `tests/` | 단계별 완료 확인 | — | 각 단계와 함께 |
| `logs/` | 검색·판정 기록 JSONL | — | 1-d |

**`data/`와 `logs/`는 통째로 저장소에 올라가지 않는다.** 규정 md는 원문 인용본이라 PDF와 배포권이 같고,
나머지는 미성년자 정보와 취재원 정보가 들어간다.

## 2. 모듈 경계

`design.md` 3.1의 "실행 모듈 3개 + 검색 자료"를 코드로 옮긴 것이다.

| 폴더 | 하는 일 | 다른 모듈을 부르나 |
|---|---|---|
| `src/common/` | 공통 타입, 로그 기록 | 아무것도 부르지 않는다 |
| `src/store/` | 문서를 절 단위로 자르고, 저장하고, 검색한다 | `common`만 |
| `src/reviewer/` | 문장을 받아 판정을 낸다 | `store`, `common` |
| `src/generator/` | 활동 기록을 받아 초안을 만든다 | `reviewer`, `common` |

화살표는 한 방향이다. `store`가 `reviewer`를 부르는 일은 없다.
**`generator`가 `reviewer`를 부르는 것이 모듈 사이의 유일한 연결이다** (design.md 3.2).

### 2.1 검색 자료를 나눠 두는 방법

`design.md` 3.3이 규정집과 관습 규칙을 섞지 말라고 했다. 코드에서는 **Chroma 컬렉션을 따로** 만든다.

| 컬렉션 이름 | 원본 | 검색 결과에 붙는 구분 |
|---|---|---|
| `regulations` | `data/regulations/*.md` | `regulation` |
| `domain` | `data/domain/*.md` (03 제외) | `domain` |
| `standards` | 교육과정 성취기준 (6단계) | `standard` |

`domain` 컬렉션의 원본은 `data/domain/` 하나다.
교사 관습·암묵지·도메인 지식을 전부 여기 둔다. 추가 취재분도 여기 넣는다.

**예외 1건** — `data/domain/03_학생실태_수준과성취도.md`는 넣지 않는다.
학생의 PC 조작 능력이나 수업 태도는 세특 문장의 위반 여부를 가르는 근거가 아니다.
이 문서는 세특 초안 생성기의 **입력 양식을 설계할 때** 읽는다 (design.md 4.2 — 입력 정의가 병목).

**`data/classification.md`도 넣지 않는다.** 판정 프롬프트를 만들 때 보는 작업용 표다.

**미정** — 도메인 문서를 지금 형태(화자별 서술) 그대로 자를지, 규칙별로 다시 묶을지는
`1-a`에서 검색 결과를 보고 정한다. 화자별 서술을 그대로 자르면 규칙이 아닌 배경
("업무가 여유롭지 않다" 등)도 검색되는데, 그것이 실제로 방해가 되는지 돌려 보고 판단한다.
**어느 쪽이든 증언 문장은 그대로 둔다. 요약하거나 표로 압축하지 않는다.**

한 함수로 두 컬렉션을 동시에 검색하지 않는다. 각각 검색하고 결과를 합칠 때 구분을 유지한다.
**섞이면 관습을 조항처럼 인용하게 된다.**

## 3. 핵심 타입

`src/common/types.py`에 둔다. **구현보다 먼저 이 파일을 만든다.**

```python
from dataclasses import dataclass
from typing import Literal

판정 = Literal["위반", "주의", "권고", "해당없음"]
규칙구분 = Literal["regulation", "domain"]
입력출처 = Literal["교사직접", "외부LLM", "자체생성"]


@dataclass(frozen=True)
class 문서조각:
    """검색 단위. 규정 md 파일의 `##` 절 하나가 기본 단위"""
    조각id: str          # 파일명 + 절 번호
    본문: str
    출처파일: str        # data/regulations/... 상대 경로
    근거줄: str          # 절의 `> 근거:` 줄 원문
    구분: 규칙구분
    적용학년: str        # "1·2학년" / "3학년" / "공통"


@dataclass(frozen=True)
class 검토결과:
    """검토기의 출력. design.md 4.1 출력 형식을 그대로 옮긴 것"""
    문장: str
    판정: 판정
    구분: 규칙구분 | None      # 해당없음이면 None
    근거: str                  # 조항 원문 인용 또는 관습 출처
    출처파일: str | None       # 근거가 실제로 있는 파일. 검증 대상
    조각id: str | None
    수정안: str | None
```

### 왜 `출처파일`을 결과에 담는가

`design.md` 3.3이 **"근거 없는 조항 번호를 대는 도구가 되는 것이 가장 하면 안 되는 실수"**라고 했다.
결과에 파일 경로가 들어 있으면 **테스트가 그 파일을 열어 근거 문장이 실제로 있는지 확인할 수 있다.**
문장으로만 적힌 원칙을 기계가 지키게 만드는 장치다.

## 4. 데이터 흐름

### 4.1 검색 자료 만들기 (1-a, 한 번만 돌리는 작업)

```
data/regulations/*.md
   ↓  절(`##`) 단위로 자른다. 표는 자르지 않는다
   ↓  절마다 `> 근거:` 줄을 본문 앞에 붙여 둔다
문서조각
   ↓  KURE로 벡터화
Chroma (collection="regulations")
```

**규정 md는 이미 절 단위로 정리되어 있다.** 파일마다 `##` 절이 있고 절마다 `> 근거:` 줄이 붙어 있다.
그래서 일반 텍스트 분할기를 쓰지 않고 `##`를 경계로 자른다.

지켜야 할 것 셋이다.

- **표를 절 중간에서 자르지 않는다.** 표 행이 머리와 떨어지면 뜻이 사라진다
- **`> 근거:` 줄을 각 조각 본문에 복제해 넣는다.** 조각 밖에 두면 검색된 조각에 출처가 없다
- **512토큰을 넘는 절은 더 나눈다** (design.md 7.2). 규정 md는 600자 기준으로 만들었으므로 대부분 걸리지 않는다

### 4.1-2 관습 규칙 적재

```
data/domain/*.md (03 제외)
   ↓  절(`##`) 단위로 자른다
   ↓  구분을 domain 으로 표시한다
Chroma (collection="domain")
```

관습 규칙은 **조항 번호를 달지 않는다.** 출처는 사람과 날짜다 (교사A, 2026-08-27).
검색 결과에 구분이 붙어 있어야 판정 출력에서 '규정 위반'과 '일반적으로 이렇게 쓰지 않습니다'가 갈린다.

### 4.2 검토 (1-b ~ 1-d)

```
세특 문장
   ↓
  ┌──────────────┬──────────────┐
  ↓              ↓              ↓
벡터 검색      BM25 검색      관습 규칙 검색
  └──────┬───────┘              │
         ↓ RRF로 순위 합침       │
    규정 조각 상위 N개      관습 조각 상위 M개
         └──────────┬───────────┘
                    ↓  구분을 유지한 채 프롬프트에 넣는다
                  LLM
                    ↓
               검토결과
                    ↓
        logs/review_YYYYMMDD.jsonl
```

### 4.3 생성과 검증 (3~4단계)

```
학생 활동 기록 → generator (프롬프트만. 검색 없음) → 세특 초안
                                                      ↓
                                                  reviewer
                                                      ↓
                                         위반 있음 → 조항을 프롬프트에 넣고 재생성
                                         위반 없음 → 완료
```

`generator`는 검색 자료를 쓰지 않는다. 근거는 `design.md` 4.2에 있다.

## 5. 설정값

전부 `config.py` 한 파일에 둔다. 코드에 숫자나 모델명을 박지 않는다.

```python
# 모델
임베딩_모델 = "nlpai-lab/KURE-v1"
생성_모델 = "claude-sonnet-4-5"        # 교체 가능해야 한다 (design.md 6장 8번)

# 검색
상위_k = 5
RRF_상수 = 60

# 분할
절_최대_토큰 = 512

# 비용
일일_토큰_상한 = 200_000

# 경로
규정_폴더 = "data/regulations"
관습_폴더 = "data/domain"
저장소_경로 = "data/.chroma"
로그_폴더 = "logs"
```

**모델명을 바꾸는 것만으로 다른 모델을 비교할 수 있어야 한다.** 그 비교 결과가 곧 실험 결과가 된다.

## 6. 로그 형식

`logs/review_YYYYMMDD.jsonl`에 한 줄씩 쌓는다.

```json
{
  "시각": "2026-10-01T14:03:11+09:00",
  "입력출처": "외부LLM",
  "문장": "...",
  "검색_조각": ["기재요령_p123-125#3", "길라잡이_p146#1"],
  "판정": "위반",
  "근거_출처파일": "data/regulations/기재요령_p123-125_세부능력및특기사항.md",
  "소요_ms": 1840,
  "토큰": {"입력": 2103, "출력": 288}
}
```

**`입력출처`를 남기는 이유** — 출처별 위반율 비교가 그대로 부가 실험이 된다 (design.md 4.1).

## 7. 테스트 배치

```
tests/
├─ test_분할.py       절 단위 분할. 표가 안 잘리는가
├─ test_검색.py       정답 절이 상위 3개 안에 들어오는가
├─ test_근거존재.py   ★ 근거로 댄 조항이 실제 파일에 있는가
└─ test_평가.py       평가셋 전수 채점
```

`test_근거존재.py`가 이 프로젝트에서 가장 중요한 테스트다.

```python
def test_근거로_댄_조항이_실제로_존재한다():
    결과 = 검토("교외 대회에서 최우수상을 수상함")
    assert 결과.판정 == "위반"
    assert 결과.출처파일 is not None
    본문 = open(결과.출처파일, encoding="utf-8").read()
    assert 정규화(결과.근거) in 정규화(본문)
```

판정이 맞았는지가 아니라 **근거가 실존하는지**를 본다.
LLM이 그럴듯한 조항 번호를 지어내는 것이 이 프로젝트 최악의 실패다.

## 8. 구현 순서

`CLAUDE.md`의 작업 순서 표와 같다. 통짜로 만들지 않는 이유는 **실패했을 때 어디가 문제인지 구분하기 위해서**다
(design.md 9.1).

| 조각 | 만드는 것 | LLM을 쓰나 |
|---|---|---|
| 1-a | 분할 + Chroma 적재 + 벡터 검색 | 아니오 |
| 1-b | BM25 + RRF | 아니오 |
| 1-c | 판정 | 예 |
| 1-d | 출력 형식 + 로그 | 예 |

1-a와 1-b에 LLM이 없다. 그래서 검색이 틀렸는지 판정이 틀렸는지 갈린다.
